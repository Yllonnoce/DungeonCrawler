# Safe Room Implementation Plan (plan B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every dungeon floor gets one locked room monsters cannot enter, where the party heals fast while the floor's monsters gather outside the longer they stay.

**Architecture:** The generator tags one dead-end room per floor as the safe room and appends it to `layout.Vaults` with a new `VaultKind.SafeDoor`, so the existing vault pipeline builds its `Door` and every later placement step (spawns, nests, traps, hazards, ambushes, portals) skips it as it skips any vault. An engine-free `SafeRoomRules` chooses the room and places the merchant's and the gatherers' cells; an engine-free `GatheringClock` keeps the pressure time. A Godot `SafeRoomController` node on the floor owns the door rule, occupancy, the regen multiplier, the gathering spawns and the HUD line; a `SafeRoomSync` message carries the HUD state to co-op clients.

**Tech Stack:** Godot 4.7.2 .NET / C#, xUnit (tests/, dev machine only), headless `--test-*` flows in `src/Core/DebugTools.cs`.

**Spec:** `docs/superpowers/specs/2026-11-02-tavern-merchant-safe-rooms-design.md` section 3 and calls 4 and 5. **Contract:** `docs/superpowers/plans/2026-11-02-tavern-shared-interfaces.md` section B (names and numbers below are copied from it; the merchant NPC itself is plan C, which consumes `FloorLayout.SafeRoom` and `SafeRoomRules.MerchantCell`).

## Global Constraints

- Engine-free rules live in `src/Adventure/Core/` or `src/Dungeon/Generation/` (both already linked into `tests/DungeonCrawler.Tests.csproj`), never reference `Godot`, and are tested with xUnit before the Godot side is written.
- Numbers, verbatim from the spec: grace 20 s, interval 40 s, cap 8 alive, empty reset 30 s, regen ×6, door opens within 2.5 m, closes 2 s after the last member is beyond 3 m, door within 10 cells of the shortest route between the stairs, room nearest the route's midpoint wins, one or two enemies per gathering group.
- The gathering clock ignores `Settings.Reinforcements`; `--no-gathering` is the only switch. `--no-portals` must not affect it.
- Co-op: the server owns door state, occupancy, regen and spawns; clients see the door through `PropEvt` as today and the HUD text through `SafeRoomSync`.
- Save: `SaveFormat.CurrentVersion` is 9 today. Plan A bumps it to 10 with `PartyDto.Gold`; this plan adds `FloorStateDto.Gathered` (int, default 0). If plan A has landed, reuse version 10 (an int that defaults to 0 needs no migration code); if not, this plan bumps to 10 itself and plan A reuses it.
- Build with `dotnet build DungeonCrawler.csproj --no-incremental -v q --nologo -clp:ErrorsOnly` before any `godot --headless` run. Headless runs that must not be disturbed use `--no-ambush --no-portals --no-gathering` as the existing flows do (`--test-abilities`).
- Shipped floor plans carry a `LayoutHash`; appending a vault before `PlaceSpawns` moves spawns on some floors and changes the hash, which the validator repairs ("adapted") rather than rejects. Task 8 refreshes the shipped hashes so the log stays clean.

## Review Focus

Spec-implied cases no task's main tests cover; each has its pin named in its owning task.

1. A downed member lying inside the room with everyone else outside: the door must close and the room must not count as occupied (occupancy is living members only). Pin: Task 5 `Occupied_CountsOnlyLivingMembers`.
2. Save while inside with gatherers waiting, then load: the gathered count survives and the clock resumes in its interval, not from grace. Pin: Task 5 `Restore_SetsSpawnedAndSkipsGrace` and Task 8 flow step "save/load keeps Gathered".
3. A floor whose dead ends are all taken by treasure vaults: the generator carves a side room off a route room rather than skipping the merchant; only when carving fails is `SafeRoom` -1. Pin: Task 1 `Choose_CarvesWhenNoDeadEndIsFree` and the -1 rate assertion.
4. A Toxic floor: the room's air stays clean for the whole floor and the HUD air tint reads clean inside. Pin: Task 3 `GasField_SafeRoomCellsNeverGas`, Task 8 flow checks `DangerAt` inside is 0.
5. Gatherers must engage the party the moment it steps out, not stand asleep: the hold state is awake (no sneak-attack bonus against them) and chases on sight. Pin: Task 6 `HoldState_IsAwake_AndChasesOnSight` (headless) plus the flow's "gatherers attack on exit" step.
