# Fortune and Misfortune Implementation Plan (Depths pillar 3, plan `fortune`)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every floor offers decisions that trade risk for power: a shrine with boons and prices, loot tables that make each chest kind different, mimics, a bound chest that hunts you, secret rooms worth finding, locks that cost, a gamble at the merchant, and drift caches in the mines.

**Architecture:** An engine-free registry (`src/Adventure/Core/Fortune/`: `Boons`, `Curses`, `Epigraphs`, `FortuneRules`, `ShrineRules`, `ChestRules`, `MimicRules`, `LockRules`, `GambleRules`, `SecretRoomRules`) holds every id, text and number; boons and curses live in the save as id lists (`AdventureDto.Boons`/`Curses`) and reach play through the pipeline skills use: `StatModifier`s summed in `CharacterState.Recalculate`, a `TriggerKind` summed in `PartyController.Trigger`, and a few static factors (`Prices.BuyFactor`, `TierRules.HazardFactor`, `ConsumableRules.HealFactor`) refreshed by one Godot node, `FortuneDirector` (child of `Game`), which also owns the event-driven boons, the shrine card's resolution, the hunt and the secret-room detection. The generator gains three end-of-pipeline passes (`PlaceShrine`, `PlaceBoundChest`, `PlaceSecretRooms`, `PlaceCaches`) so ordinary floors' spawns and room indices stay as they were; `DungeonBuilder` gives every chest a `TableId` by kind. Co-op: the server resolves everything; six new messages carry the shrine card, the fortune lists and the Lucky Dip.

**Tech Stack:** Godot 4.7.2 .NET / C#, xUnit (`tests/`, dev machine only), headless `--test-fortune` flow in `src/Core/DebugTools.cs`.

**Spec:** `docs/superpowers/specs/2026-11-07-the-depths-update-design.md` section 3 (binding; numbers verbatim). **Contract:** the shared-surface names in `/tmp/.../plan-contract.md` item 8 are used as written; Task 1 adds any that the earlier plans (combat-feel, items-and-builds, writing) and the parallel one (elites-and-bosses) have not landed, with exactly that shape, so the merge dedupes.

## Review Focus

1. A floor with no room that can hold a shrine (tiny or all rooms excluded) must build with no shrine and no error, and the next floor must try again. Pin: Task 4 `Choose_ReturnsNull_OnTheTavern_AndNeverBlocksTheRoute`.

5. A locked chest jammed and then opened with a key, saved, loaded: it is open, not jammed-and-full. Pin: Task 10 `Jam_IsClearedByAKey_AndSurvivesSave` (flow step).
