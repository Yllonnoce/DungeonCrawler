# A Party That Talks Implementation Plan (plan: writing)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The four heroes talk to each other (banter), react to the specific thing that just happened (fifteen new bark triggers and eight-deep banks for the old ones), answer a cheer, get an epitaph when they fall, and the villain has words for elites, shrines, mimics, lost allies and gambles; companions' lines show in the subtitle strip with the speaker's name.

**Architecture:** Every line lives in an engine-free bank under `src/Adventure/Core/Voice/` as C# string arrays keyed by roster name, then class, then generic, with a `TopUp(BarkSet, classId)` that pours stock into a campaign's bark set exactly as `KillBarks`/`IdleBarks`/`TravelBarks` do today (`src/Adventure/AdventureDirector.cs:153-180`, `186-220`). Rates and sizes are constants in `*Rules` classes. The Godot side is one new partial file, `src/Adventure/AdventureDirector.Talk.cs`, that wires the new `EventBus` events to barks, runs the banter queue, the cheer, the run flags and the wipe-cause inference; `AdventureDirector.cs` itself changes in three places (`Bark`, `_Ready`, `_Process`). Co-op stays server-authoritative: every line the server picks reaches clients through the existing `BarkMsg`; a client's V press is a new `CheerIntent`; bodies cheer through the existing `EmoteEvt`.

**Tech Stack:** Godot 4.7.2 .NET / C#, xUnit (`tests/`, dev machine only, `tests/DungeonCrawler.Tests.csproj` already links `../src/Adventure/Core/**/*.cs`, `../src/Net/Core/**/*.cs`, `../src/Save/Core/**/*.cs`, `../src/Party/Core/**/*.cs`), headless `--test-*` flows in `src/Core/DebugTools.cs`.

**Spec:** `docs/superpowers/specs/2026-11-07-the-depths-update-design.md` section 6 ("A party that talks"), plus the shared surface in the contract (EventBus events, `BarkTrigger`/`TauntTrigger` values, the `"cheer"` key). Other pillars consume: run-structure reads `Epitaphs` and `AdventureDirector.LastWipe` for its death card; elites/fortune raise `EliteSeen`, `EliteSlain`, `MimicSprung`, `ShrineUsed`, `BoonTaken`, `CurseTaken`, `Gambled`, `SecretFound`; combat-feel raises `PerfectBlow`, `Parried`, `PerfectBlock`, `MemberFell`.

## Global Constraints

- Engine-free rules live in `src/Adventure/Core/**` (already linked into the test project), never reference `Godot`, and are tested with xUnit before the Godot glue.
- Numbers, verbatim from the spec: banter 2–4 lines, 45 exchanges, every hero pair at least five, one travel grumble in three becomes banter, safe room after **8 s** of rest, lines **1.4 s** apart, stop if a fight starts; **eight** lines per hero per new trigger, **five** per class, **five** generic; Hurt/Loot/Downed/Revived/BossSeen/LevelUp grow to **eight** per hero and use `ChooseOrOldest`; cheer: every other living hero answers, **one each, 1.2 s apart**, the first within **2 s**, **20 s** cooldown; LowHp = first time under **25%** on a floor; epitaph bank keyed by **gas, press, spikes, boss, horde, elite, fall, mimic, bomber, generic**, escalating with the wipe count on that floor; two stock villain lines per new `TauntTrigger`; six asides in the shipped campaign; floor 3's press line moves from `MemberDowned` to `Crushed`.
- Register: British dry wit, bathos, short clipped sentences, no modern idiom, no fourth wall. Brand, Wren and Ilex are men; **Sable is a woman** (memory: character sexes for voice). The villain is never funny on purpose.
- Stock banks (used by AI and offline campaigns) must not name **Gorm, the Verger, Ashmere, Dunmarrow, the Gullet, the alderman or "this parish"**; a test greps for them. The shipped `campaign.json` may (it is that campaign).
- Every bark line is at most **90** characters (the planner's rule, `PromptBuilder.cs:73`); taunts at most **220** (`CampaignRepair.MaxLine`).
- New text has no audio until the owner bakes it (`VoiceLineId.For` hashes text; a changed line is a new id): everything here ships as subtitle + log and is wired for the existing bake flags. Do not run a bake.
- Rate limits stay: 5 s global gap and 25 s per member per trigger for reactive barks (`AdventureDirector.cs:202-203`); kill/dance keep `KillBarks.GlobalGapSeconds`/`CooldownSeconds`. Scripted lines (banter, cheer answers) bypass the gaps but still set `_lastBark` so nothing else talks over them.
- Co-op: server-authoritative. The one new message is `CheerIntent` (client to server); `Protocol.Version` becomes **7**, `Protocol.MessageKindCount` **81**. Say so in the commit. If co-op's plan has already bumped to 7 for `PingEvt`, append `CheerIntent` after it and bump to 8.
- Save: v11 (run-structure bumps the version; if it has not landed, bump to 11 yourself, defaults only). This plan adds one DTO field, `AdventureDto.GagCounts` (`Dictionary<string,int>`, default empty): no migration code.
- Build with `dotnet build DungeonCrawler.csproj --no-incremental -v q --nologo -clp:ErrorsOnly` before any `godot --headless` run; game flags after a bare `--`; `--no-ambush --no-portals --no-gathering --lethality=1` unless the test needs them.
- Collision discipline (files other plans own; add exactly what is listed, nothing else): `src/UI/Hud/Hud.cs` (combat-feel): `public void ShowBark(string speaker, string text, float seconds)` plus the private flag it needs; `src/Party/Adventurer.cs` (combat-feel): `public void PlayCheer()`; `src/Party/PartyController.cs` (combat-feel/items): one `else if` in `_UnhandledInput` and one line in `ShopBuy`; `src/Save/Core/SaveDtos.cs` (run-structure): `AdventureDto.GagCounts`; `src/Dungeon/Props/Trap.cs` (nobody): one raise in `Spring(Adventurer)`; `src/Adventure/Npc.cs` (nobody): one raise in `AskToJoin`; `src/Net/ServerWorld.cs`, `src/Net/ClientWorld.cs` (co-op): the exact cases listed in Task 9.

## Review Focus

Spec-implied cases no task's main tests cover; each has its pin named in its owning task.

1. A banter exchange whose second speaker goes down (or is parked in co-op) between line one and line two must not have a dead body speak: the queue re-checks the speaker is alive before each line and drops the rest. Pin: Task 9 `BanterRun_DropsLines_WhenASpeakerIsNotLiving` (engine-free) and the flow's "banter aborted by a fight" step.
2. A cheer with one living hero (solo, everyone else down) must still say the cheer line and schedule no answers, and a cheer pressed while downed must do nothing. Pin: Task 3 `Answerers_ExcludesTheCheererAndTheDowned` and Task 9 flow step 5.
3. A campaign written before the new triggers existed (the shipped Gullet, an older AI bake) has no lines for them: the lazy `TopUp` in `Bark()` must fill them on first use, in that hero's voice, not fall silent. Pin: Task 2 `TopUp_FillsEveryReactiveTrigger_ForAShippedStyleSet` and Task 8 flow step 3 (the shipped campaign has no TrapSprung lines; a bark still comes).
4. Narration and a bark landing in the same second: the subtitle shows the narration, the bark is heard (if voiced) and logged, and a bark never overwrites a narration still on screen; a later bark may replace an earlier bark. Pin: Task 8 flow step "narration wins" (raise `Narration`, then `TrapSprung`; `Hud` subtitle text is the narration).
5. An epitaph for a cause with no note (a party that simply died to ordinary creatures) must pick `generic`, never throw on an unknown cause id, and escalate past the fourth wipe without an index error. Pin: Task 5 `Pick_UnknownCause_FallsBackToGeneric` and `Pick_ClampsPastTheFourthWipe`.

        foreach (var t in new[] { BarkTrigger.Kill, BarkTrigger.Idle, BarkTrigger.Dance, BarkTrigger.Travel, BarkTrigger.Possess, BarkTrigger.Cheer, BarkTrigger.CheerAnswer })

        {
            var own = ReactiveBarks.For(t, name, cls);
            Assert.True(own.Count == 8, $"{name} {t}: {own.Count}");
