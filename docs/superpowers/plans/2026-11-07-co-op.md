# Co-op ("Friends") Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Friends on a server stop fighting over the stairs (a ready-check with a 15 s majority clock), can point at things (a 2 s ping with their name, in the world and on the minimap), and everyone can type in chat, in solo and on the host too.

**Architecture:** An engine-free `ReadyCheck` state machine in `src/Net/Core` decides when a stairs vote goes, waits or is called off; the server owns one instance in a new partial `ServerWorld` file and tells every HUD where it stands with a `StairsReadyMsg`. `Stairs.Confirm`/`Decline` send a `StairsReadyIntent` from a client, and `Stairs.Interact` on the server hands the decision to the ready check when two or more players are online (solo and one-player servers call `Game.ChangeFloor` as today). An engine-free `PingBoard` keeps the live pings; a `PingMarkers` node under the HUD draws them as `Label3D`s and `MapView` draws them on the minimap; `PingIntent`/`PingEvt` relay them through the server. The chat line loses its client-only guard and writes to the log elsewhere.

**Tech Stack:** Godot 4.7.2 .NET / C#, xUnit (tests/, dev machine only), headless `--test-*` flows in `src/Core/DebugTools.cs`, `scripts/net_test.sh` (headless server + client).

**Spec:** `docs/superpowers/specs/2026-11-07-the-depths-update-design.md`, pillar 7 "Friends" (lines 358-366), constraints at lines 78-93 (keys: ping **X**). This plan runs **last**: run-structure's recap and writing's Cheer relay are already in the tree.

## Review Focus

Spec-implied cases no task's main tests cover; each has its pin named in its owning task.

1. The only other player is down when someone says Yes: the floor must change at once (downed players are not "living"), not wait 15 s for a vote the downed player cannot cast. Pin: Task 1 `Vote_WithOneLivingPlayer_GoesAtOnce`.
2. A player leaves mid-vote: the remaining votes are re-counted against who is left, so two Yes votes from the two players still online go even though the leaver never voted. Pin: Task 1 `Tick_ALeaverStopsCounting`.
3. Two players, one Yes, 15 s of silence: one of two is not a majority, so the check is called off and the HUD line clears on every screen (nobody is left staring at "1/2 ready"). Pin: Task 1 `Timeout_WithoutMajority_Cancels` and Task 3's cancel broadcast assertion in the server trace (`ready-cancel`).
4. The stairs lock between the first Yes and the Go (a floor objective re-seals them, or the voter was not on the landing): the server re-checks `Locked` at Go time and logs the lock reason instead of changing floor. Pin: Task 3 step 3 (`OnReadyVerdict` re-checks `stairs.Locked`), proven by the headless flow's rule table printing the lock path.
5. Ping spam and ping teleport: a client that fires twenty `PingIntent`s a second or a point 300 m away must not flood everyone's screen; the server enforces the 1 s cooldown per player and a 45 m range from the body. Pin: Task 4 `Server_RefusesAPingInsideTheCooldown` (engine-free `PingRules.Accepts`) and the flow's cooldown step.

  ```csharp
  public static class ReadyCheckRules
  {
      public const float TimeoutSeconds = 15f;
      public const int MinPlayers = 2;
      public static bool Needed(int onlinePlayers);            // onlinePlayers >= MinPlayers
      public static bool Majority(int ready, int total);       // total > 0 && ready * 2 > total
      public static string HudLine(int count, int total, int secondsLeft, int direction); // "Descend? 1/3 ready · 12 s" (direction > 0) / "Climb? ..." (direction < 0); "" when total == 0
  }
  public enum ReadyVerdict { Pending, Go, Cancelled }
  public sealed class ReadyCheck
  {
      public bool Active { get; }
      public string StairsRef { get; }          // "" when inactive
      public int Direction { get; }
      public double StartedAt { get; }
      public IReadOnlySet<int> Ready { get; }   // member indices that said Yes
      public int ReadyCount(IReadOnlyCollection<int> living);                 // |Ready ∩ living|
      public float SecondsLeft(double now);                                   // clamp(TimeoutSeconds - (now - StartedAt), 0, TimeoutSeconds); TimeoutSeconds when inactive
      public ReadyVerdict Vote(int member, bool yes, string stairsRef, int direction, IReadOnlyCollection<int> living, double now);
      public ReadyVerdict Tick(IReadOnlyCollection<int> living, double now);
      public void Clear();
  }
  ```
  Semantics: `Vote(yes)` while inactive starts the check (`StartedAt = now`, `Ready = {member}`) and then evaluates like `Tick`; `Vote(yes)` for a different `stairsRef` while active clears and starts afresh; `Vote(yes)` twice by one member counts once; `Vote(no)` while active returns `Cancelled` and clears; `Vote(no)` while inactive returns `Pending` and does nothing. `Tick`: inactive returns `Pending`; `ReadyCount(living) >= living.Count && living.Count > 0` returns `Go`; else when `now - StartedAt >= TimeoutSeconds` returns `Go` if `Majority(ReadyCount(living), living.Count)` else `Cancelled`; else `Pending`. `Go` and `Cancelled` both leave the check cleared (`Active == false`).
